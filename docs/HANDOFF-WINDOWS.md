# EdgeLink: Windows → Mac handoff

Дата: 11 октября 2026, Asia/Dubai. Ветка обмена: `windows/input-validation`.

## Текущий результат: интерфейс и трей

Проверенный коммит исходников: `57c7e2b2f5bd3bb1437af963aa3d9233622c0fd3`, версия 0.3.4. Этот раздел заменяет сведения о текущей установленной сборке ниже; предыдущий этап сохранён как история. Новый релиз не публиковался, Mac-часть и протокол не изменялись.

Windows-интерфейс переработан по структуре Mac: верхние вкладки, компактная схема экранов, статус с действием в одной строке, одинаковые карточки мыши и звука. Показатели соединения перенесены в параметры. Включена нативная тёмная тема .NET 10; кнопки, карточки и флажки имеют собственную отрисовку с читаемыми отключёнными состояниями. Смена стороны Mac обновляет схему и текст перехода. При узком окне карточки и строки перестраиваются вертикально.

Крестик скрывает окно, сохраняя подключение, ввод и звук. NotifyIcon позволяет открыть окно, подключиться/отключиться и полностью выйти. Повторный запуск EXE открывает тот же экземпляр. Очистка ресурсов перенесена на фактическое закрытие; обновление и завершение сеанса Windows не блокируются. То же меню доступно правой кнопкой в окне.

Сборка и проверки выполнены на том же локальном Windows-ПК, 96 DPI / 100%, 2560×1440. Перед диагностикой подтверждено отсутствие обычного процесса. Промежуточная сборка без меню в окне была остановлена по проверенному пути EXE для замены; это не учитывается как проверка штатного выхода. Финальная сборка повторно собрана после получения опубликованного коммита, без предупреждений, с `TreatWarningsAsErrors=true`.

Tray checks используют настоящий NotifyIcon и обработчики меню. Проверены открытие, восстановление свёрнутого окна, выход и закрытие при обновлении. Проверка Windows shutdown вызывает только событие закрытия, реального завершения сеанса не было. Прямой щелчок значка в системной области уведомлений не выполнялся: доступный инструмент не предоставляет окно панели задач; поведение меню проверено диагностикой и тем же меню в окне.

Раскладка проверена при клиентских размерах 664×521 (минимальное окно), 800×600, 1060×760 и 1400×900, включая три цикла переключений, четыре шага мастера, длинный статус, прокрутку до последней карточки и обе стороны Mac. Другие DPI пока не проверялись. Диагностические PNG созданы без личных настроек и ключа; `DrawToBitmap` отличается от живой отрисовки системных рамок и некоторых ComboBox. Живая отрисовка проверялась отдельно. Клавиатурное действие выполнено инструментом автоматизации, не является тестом физической MCHOSE.

Результаты и безопасные снимки: [`validation/windows-ui-tray-2026-10-11/`](validation/windows-ui-tray-2026-10-11/). Программный набор 38 PASS предыдущего этапа остаётся применим к неизменённым вводу, протоколу и аудиобуферу; повторно на этом этапе он не запускался.

SHA-256: `236d88bab9edd6dfdb9f3ce033475d2f6d6b3888b70a6c9b61a041363e54729f`. Соединение восстановилось автоматически. Предыдущие EXE сохранены локально в игнорируемой папке `work/native-validation`; настройки и ключ не опубликованы.

Во время автоматизации интерфейса счётчик прерываний аудио вырос с 0 до 6, запас — с 20 до 50 мс. Это наблюдение диагностических счётчиков, без прослушивания и без установленной причины; качество воспроизведения пока требует проверки пользователем после окончания автоматизации. Непрерывный рост пакетов при скрытом окне подтверждает сохранение сессии, а не отсутствие слышимых прерываний.

Следующий шаг: пользователь оценивает новый интерфейс, физическую плавность Lamzu при 4000/8000 Гц, переходы влево и обратно, возврат Ctrl+Alt+Esc, клавиатуру MCHOSE и звук Dark Project. ## Результаты

Обычный EdgeLink полностью закрыт штатной кнопкой окна. Отсутствие процесса проверено перед диагностикой. Каждый диагностический процесс завершился; проверялись свежие отчёты, а исходные результаты сохранены отдельно.

| Проверка | База d210078 | Исправленный 5e9f0dc |
| --- | --- | --- |
| Self-contained `win-x64` single-file publish, `TreatWarningsAsErrors=true` | PASS, без предупреждений | PASS, без предупреждений |
| `EdgeLink.exe --input-checks` | Exit 0, 3/3 PASS | Exit 0, 3/3 PASS |
| Ответ потока ввода при остановке UI на 300 мс | 0,2219 мс | 0,2122 мс |
| `EdgeLink.exe --layout-checks` при 96 DPI | Exit 1: 54 сценария, 163 сообщения об ошибках | Exit 0: 63 сценария, `Failures: []` |
| `dotnet run --project source/checks/Checks.csproj -c Release -p:TreatWarningsAsErrors=true` | 38 PASS | 38 PASS, тот же проверенный код |

Input checks подтверждают отдельный поток, отсутствие регистрации Raw Input при управлении ПК и сохранение исходного состояния регистрации после остановки. Они не измеряют плавность физической мыши или задержку реального ввода при 4000/8000 Гц и не проверяют включение Raw Input при управлении Mac.

Программный набор проверил криптографию, ABI структур Windows x64, объединение движений и пробуждение отправителя, адаптивный аудиобуфер и проверки обновлений. Измерено 128 байт выделений на 100000 программно опубликованных движений. Это программный результат, а не нагрузка реальной Lamzu. Swift/.NET интеграционный набор `source/run-checks.sh` здесь не выполнялся; прежние результаты Mac остаются в `verification.txt`.

Layout checks используют настоящие WinForms-контролы и шрифты Windows: размеры клиентской области 800×600, 1060×760 и 1400×900, три цикла навигации, все четыре шага мастера, перенос общих селекторов, длинное сообщение на главной странице. Добавлены девять проверок прокрутки настроек до последней карточки и проверка полных подписей навигации. Снимки выбранных сценариев просмотрены. `DrawToBitmap` не полностью воспроизводит нативную отрисовку ComboBox; пустые поля на диагностических PNG не являются доказательством пустого живого селектора.

Результаты без секретов и личных настроек: [`validation/windows-2026-10-11/`](validation/windows-2026-10-11/):

- `input-before.json`, `layout-before.json` — первый запуск базового 0.3.4.
- `input-checks.json`, `layout-checks.json` — последний запуск опубликованного коммита 5e9f0dc.
- `software-checks.txt` — полный вывод программного набора; исходники набора не менялись.

Текущие штатные отчёты также остаются в `%TEMP%/EdgeLink-input-checks.json` и `%TEMP%/EdgeLink-layout-checks/report.json`; остальные диагностические PNG — в последней папке.

## Изменения Windows

1. `Dashboard.cs`: колонке боковой панели задана ширина 100% доступной области. Без `ColumnStyle` WinForms оставлял дочерние панели шириной 200 px даже в колонке 148/190 px. Компактная колонка расширена до 168 px, чтобы целиком помещалось «Подключение».
2. `Layout.cs`: после изменения `AutoScrollMinSize` базовый `ScrollableControl` обновляет диапазон прокрутки до применения смещения. Вложенный запрос layout раньше блокировался защитой от рекурсии: при высоте содержимого 1173 px фактический диапазон оставался 1056 px, и нижняя карточка была недоступна.
3. `LayoutChecks.cs`: добавлены реальные границы в ошибки обрезания, проверки подписей навигации и прокрутки при каждом размере/цикле, снимки главной страницы, настроек и шагов мастера.

Версия остаётся 0.3.4. Ввод, протокол, звук и Mac-часть этим изменением не менялись. Новый релиз не публиковался.

## Следующий шаг

Mac-чату: получить ветку и изучить Windows-исправления и JSON; Mac обновлять только ради этих изменений не требуется. Для получения результата:

```sh
git fetch origin
git switch --track origin/windows/input-validation
```

Если ветка уже существует локально, перейти на неё и выполнить `git pull --ff-only`. Не публиковать новый релиз до согласования результатов реального ввода и звука.

Windows-чату совместно с пользователем: для каждой частоты 4000/8000 Гц оценить движения на ПК при закрытом и подключённом EdgeLink, выполнить несколько переходов между экранами и аварийный возврат, проверить набор/модификаторы на Mac и прослушать звук. Записать частоту, состояние соединения и место проявления рывков; дополнить этот handoff фактическими результатами. Если рывки сохраняются, собирать измерения нагрузки/задержек Windows ввода в этом сценарии, не выводить отсутствие проблемы из пройденных программных проверок.
