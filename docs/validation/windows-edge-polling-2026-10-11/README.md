# Отключение mouse hook на ПК: финальная Windows-проверка

11 октября 2026, Asia/Dubai. Ветка `windows/input-validation`, исходники/установленный EXE `0e09116ca209ff767bfb8892e2d599db4431a043`, версия 0.3.4. Физический Windows 11 Pro 25H2 / build 26200.9457, 16 логических процессоров, 2560×1440 / 100%. Настроенная частота Lamzu Maya X — 4000 Гц со слов пользователя; аппаратный USB polling rate не измерялся.

## Изменение

PC-side движения больше не проходят через mouse hook EdgeLink. Отдельный input thread наблюдает GetCursorPos по обычному WM_TIMER, запрошенный интервал 16 мс, без повышения точности таймера на ПК. Таймер запускается при Configure, выключается при Disconnect/потере связи/завершении потока. Поскольку [WM_TIMER имеет низкий приоритет](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-timer), фактическая реакция перехода может быть дольше 16 мс. Пользователь согласовал этот компромисс.

Mouse hook/Raw Input и повышенная точность таймера включаются на время управления Mac и снимаются при возврате. Проверка удерживаемых кнопок повторяется перед захватом; сбой установки/регистрации/ClipCursor откатывает вход. Парковка на краю не запускает переход без нового движения. Удерживаемые клавиши/кнопки, границы по высоте, inward rearm и cooldown 200 мс сохранены. Клавиатурный hook, wire protocol и аудио не менялись.

## Физическая проверка пользователем

На установленном EXE проверены переходы ПК → Mac слева → ПК, клики и прокрутка на Mac, аварийный возврат Ctrl+Alt+Esc. Ответ: **«Всё работает нормально»**. Удержание Shift или кнопки мыши блокирует перенос; после отпускания и нового движения к краю переход работает. Ответ: **«Да, удержание блокирует переход»**.

Автоматическое подключение проверено отдельно через живое окно. Во время первых осмотров после установки интерфейс показывал одно аудиопрерывание; точное время/причина/слышимость не установлены. Агент звук не прослушивал, отдельное подтверждение качества звука на этом этапе не запрашивалось.

## Чистое сравнение на 4000 Гц

Точный пассивный observer и методика из [предыдущего измерения](../windows-mouse-impact-2026-10-11/README.md) сохранены без изменения. Отдельный процесс ставит WH_MOUSE_LL последним, измеряет QPC вокруг CallNextHookEx для физических WM_MOUSEMOVE, передаёт ввод дальше, исключает injected события. Raw Input регистрация принадлежит observer, не приложению. Только агрегаты времени/счётчиков, без координат, кнопок, клавиш, сетевых данных и device IDs.

3 секунды прогрева + 20 секунд выборки; пользователь двигает мышью по центру ПК, без перехода на Mac. Во время выборки агент не управляет UI и не снимает интерфейс. Включённый чистый прогон выполнен после пользовательской проверки переходов и возврата. Затем пользователь полностью завершил EdgeLink для свежего контроля: перед стартом 0 процессов, observer в интерактивной session 2. Следующий обычный процесс начал работу через 9,3 секунды после записи off-отчёта; контрольный интервал полностью прошёл без приложения.

Разница типичных значений находится у нижней границы разрешения измерения; её нельзя трактовать как ускорение от включения приложения. Среднее и обычные процентили соответствуют состоянию без приложения. Прежняя добавочная стоимость постоянного hook 0,134–0,160 мс не воспроизводится. Единичный максимум с приложением выше, причина не установлена.

CPU всего EdgeLink за полный 23-секундный интервал с прогревом: **2,928% всей машины**, или 46,85% относительно одного логического процессора. Это всё приложение с UI/сетью/аудио, не только sampling. Нагрузка не снизилась относительно прежних 2,457–2,847%; вывод о снижении общего CPU не делается. Observer CPU: 0,429% с приложением и 0,484% без него. Рабочий набор EdgeLink на конце on-прогона — 223,93 МиБ.

### Исключённые интервалы

`excluded/on-with-mac-transfers.json` — предварительный прогон, среднее 0,00336 мс, максимум 1,3724 мс. `excluded/on-interrupted.json` — второй предварительный прогон, всего 1708 событий и длительные остановки движения. Пользователь сообщил о случайных переходах на Mac и попросил остановить, затем повторить измерение. Эти файлы сохранены для прозрачности, **не используются как сравнение PC-side обработки**. Переход меняет состояние hook, а hook, установленный после observer, меняет порядок измеряемой цепочки. Computer Use дважды останавливался физической Escape при подготовке контроля; нативные действия не продолжались до нового запроса пользователя. Чистый off-прогон выполнен после ручного закрытия пользователя без Computer Use.

## Ограничения и следующий шаг

Измеряется оставшаяся цепочка CallNextHookEx, не время сенсор → пиксель, не весь путь мыши и не frame time игры. Наблюдатель сам добавляет hook и CPU. Ручная скорость движения, фоновые приложения и нагрузка не фиксированы, сравнение не рандомизировано. Raw observer получил около 125 движений/с в обоих сценариях; это доставка фоновой регистрации, не аппаратная частота опроса и не доказательство потери отчётов. Разница количества hook событий также не доказывает потерю данных.

Проверка 8000 Гц, правая физическая конфигурация Mac, другие DPI и отсутствие редких рывков вне коротких выборок не подтверждены. Следующий шаг: аппаратные 8000 Гц/наблюдение переходов, отдельный профиль общего CPU при необходимости и объединение с Mac-веткой `mac/el-icon-validation` перед согласованным релизом. Публичный релиз остаётся 0.3.4; секреты и личные настройки в отчёт не включены.
