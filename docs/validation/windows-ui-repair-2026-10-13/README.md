# Windows: исправление интерфейса и состояния соединения

13 октября 2026. Ветка `windows/input-validation`. Исходная база —
`dc872a72292721030c9c3a580f0a8df2391ac8ae` после обновления из main.
При начале работы отслеживаемых локальных изменений не было.

На физическом Windows 11 Pro 25H2 (build 26200), 96 DPI, .NET SDK 10.0.401
собрана и установлена версия **1.0.3** из
`5f77d1ab6fa8c769ab967be386e4aca63f9d3ce7`. `build.json` содержит точную
версию EXE, размер и SHA-256. Позднейшие изменения диагностических отчётов
и тестов документируются отдельно; они не меняют установленный интерфейс.

## Исправления

- Нулевая толщина рамок скрывала выделение владельца ввода. Теперь ПК или
  Mac имеет видимую рамку и лёгкую заливку; статус, подписи устройств,
  направление и кнопка отражают одно состояние соединения.
- Согласованы отступы, скругления, размеры ноутбука/монитора и выравнивание
  раскрытой диагностики. Полоска вкладок снова имеет постоянную ширину 24 px
  и перемещается через compositor за 160 мс с текущей позиции.
- Статистика сразу обновляется при раскрытии; секундный таймер работает
  только на странице соединения с раскрытой диагностикой, живой связью и
  видимым несвёрнутым окном. Таймеры создаются до построения страниц.
- Выбранный монитор сохраняется по DeviceName, а актуальные границы
  разрешаются при подключении. Ошибки импорта/загрузки сопряжения сохраняются
  при обновлении состояния.
- `--background-ui-checks` проверяет настоящий WinUI вне экрана без
  активации, ввода, аудио, сети, настроек и значка трея.
  `--status-json PATH` считывает безопасный снимок уже работающего приложения.
  `--start-hidden` запускает обычное приложение в трее.

`background-ui.json` и `layout.json` — отчёты точного установленного исходника.
`ui/` — нативные RenderTargetBitmap **диагностических состояний**, без личных
настроек и ключа. Это не снимки пользовательского рабочего стола и не
доказательство реального переключения управления. `installed.json`,
`live-before.json`, `live-after.json` — безопасные сведения об установке и
двух снимках реального приложения. В последнем снимке underruns=0; пакетный
счётчик подтверждает приём, но не слышимое качество или полную задержку.

Computer Use, синтетический ввод и активация проверочных окон не применялись.
Input/tray/fullscreen режимы на пользовательском ПК в этой задаче не
запускались: пользователь продолжал работать. Их результаты GitHub Actions
нужно отличать от аппаратных проверок на этом ПК.

## Ограничения и следующий шаг

PASS: core 43, input 15/15, tray 17/17, installer 5/5, layout 111/0,
background states 137/0, background layout 111/0. Отчёты в `ci/`.

повторная успешная проверка не доказывает отсутствие любой редкой ошибки.

кода**: [attempt 2 полностью PASS](https://github.com/b0rdik/EdgeLink/actions/runs/38414598841/attempts/2).
