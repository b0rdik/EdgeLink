# Влияние EdgeLink на обработку мыши: 4000 Гц

11 октября 2026, Asia/Dubai. Физический Windows 11 Pro 25H2 / build 26200.9457, 16 логических процессоров, экран 2560×1440 / 100%. Пользователь указал 4000 Гц для Lamzu Maya X и выполнял реальные движения по центру экрана ПК. USB polling rate аппаратным анализатором не измерялся.

Проверенная установленная сборка: `0.3.4+3d001b70b2b17c630ac68d43c9f6d6efda2c87ea`, SHA-256 `928523bfce8700d3054d382fd7bb2bee28b314a7443cbc073ebb44b683895085`. Исходники приложения не менялись. Сессия Shell/EdgeLink/Explorer совпадает, UserInteractive=true. Перед первым прогоном и после последнего в живом интерфейсе подтверждено подключение к Mac; во время измерений UI не инспектировался и агент ввод не генерировал.

## Методика

Отдельный пассивный .NET 10 процесс с message-only Win32 окном устанавливает WH_MOUSE_LL последним, когда EdgeLink уже работает либо полностью закрыт. Для физических WM_MOUSEMOVE фиксирует QPC-время вокруг CallNextHookEx, возвращая его результат без подавления/изменения событий. Injected события не измеряет. Координаты, кнопки, клавиши, содержимое памяти приложения, сетевые данные и идентификаторы устройств не сохраняются. Нормальный приоритет observer, без изменения системных таймеров; TieredCompilation отключена только для observer. Массивы заранее выделены, вывод выполняется после выборки. При завершении hook и отдельная Raw Input регистрация снимаются.

Счётчик Raw Input получает относительные ненулевые движения всех мышей через RIDEV_INPUTSINK в отдельном процессе. Он не заменяет регистрацию EdgeLink: регистрации привязаны к процессу. Его интервалы характеризуют доставку наблюдателю, а не время USB-пакета и не полную задержку курсора.

Три сценария: включён с открытой главной → полностью закрыт через меню → повторно запущен с открытой главной. В каждом 3 секунды прогрева и 20 секунд выборки. Перед закрытым сценарием нативная диагностика завершилась и подтверждено отсутствие обычного процесса. Перед третьим прогоном пользователь прервал Computer Use клавишей Esc; повтор выполнен в следующем ходе после явного запроса продолжить. Первый пробный интервал без физических событий в сравнении не используется.

CPU читается по суммарному процессорному времени за весь интервал около 23 секунд, включая прогрев. Проценты всей машины делятся на 16; проценты одного логического процессора представлены отдельно. CPU относится ко всему EdgeLink с UI, сетью и аудио, а не только hook. Память — рабочий набор на конце интервала, не частная RAM.

## Что можно заключить

В двух прогонах с EdgeLink стабильно выше время оставшейся цепочки перехватчиков, чем после его полного выхода. Программа имеет измеримые накладные расходы на PC-side обработку мыши в этих условиях. По устройству [LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc) вызов доставляется потоку, установившему hook; измерение включает переход к этому потоку, планирование и оставшуюся цепочку. Это не отдельный таймер только тела Input.Mouse и не измерение от сенсора до экрана.

Observer добавляет собственный hook, Raw Input обработку и CPU; абсолютные числа нельзя считать точной добавленной задержкой без наблюдателя. Скорость ручного движения не фиксирована, сравнение не рандомизировано, третий прогон отделён перерывом. Разница количества hook событий не доказывает потерю USB-отчётов. Raw Input доставил примерно 125 движений/с во всех состояниях: эти данные не подтверждают и не опровергают настройку 4000 Гц. Процентиль 99,9 не является максимумом.

Редкие рывки за пределами двух 20-секундных выборок, задержка изображения, DPC/ISR, GPU/frame time игр, 8000 Гц, переходы на Mac и физическая клавиатура не проверялись. Следующий шаг: профиль PC-side постоянного hook и эксперимент с уменьшением его стоимости, затем повтор сравнения и пользовательской оценки. На этом этапе исправление не выполнялось.

## Повторение

Исходник использованного observer включён в `observer/`. Его поле configuredPollingHz фиксировано на 4000 — для другой настройки это поле нужно изменить; это метаданные со слов пользователя, не автоматическое определение частоты.

```powershell
# Из корня репозитория; dotnet 10 должен быть доступен.
dotnet build docs/validation/windows-mouse-impact-2026-10-11/observer/MouseImpact.csproj -c Release -o work/mouse-impact/bin
$env:DOTNET_TieredCompilation='0'
# Укажите PID уже работающего EdgeLink; во время замера двигайте физическую мышь.
dotnet work/mouse-impact/bin/MouseImpact.dll 20 work/mouse-impact/on.json connected-home <PID>
# Затем штатно завершите EdgeLink и убедитесь в отсутствии процесса:
dotnet work/mouse-impact/bin/MouseImpact.dll 20 work/mouse-impact/off.json app-fully-closed 0
# Перезапустите EdgeLink, дождитесь подключения и повторите включённый сценарий с новым PID.
```

Не запускайте второй EdgeLink в ходе выборки: новый hook изменит порядок цепочки и границы измерения. Каждый запуск observer должен происходить после запуска проверяемого приложения. Результат без физических событий не является проверкой мыши.
