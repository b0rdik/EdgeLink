# Windows: предварительное измерение ресурсов EdgeLink

11 октября 2026 (Asia/Dubai). Проверенная сборка: `0.3.4+57c7e2b2f5bd3bb1437af963aa3d9233622c0fd3`. Исходники приложения не менялись.

Локальный Windows 11 Pro 25H2, build 26200.9457; Ryzen 7 9850X3D, 8 ядер / 16 логических процессоров по Windows; экран 2560×1440, 100%. Обычное приложение сохраняло подключение к Mac 0.3.3 с передачей и воспроизведением звука. Скрытие в трей не разрывало сессию.

## Методика

`Measure-EdgeLink.ps1` читает счётчики указанного процесса через `System.Diagnostics.Process` раз в секунду, 30 раз. Средний CPU рассчитан по сумме пользовательского и системного процессорного времени всех потоков, делённой на фактическое время наблюдения и 16 логических процессоров. 100% в таблице означает всю мощность CPU, как в Диспетчере задач; 6,25% соответствует полной загрузке одного логического процессора. Отдельно в JSON сохранён процент относительно одного логического процессора.

Рабочий набор — резидентные страницы процесса в физической памяти, включая общие страницы. Private committed — частная выделенная виртуальная память; это не отдельная оценка физической RAM. Единица памяти — МиБ (1024² байт). Сохраняются все секундные выборки, диапазоны памяти, потоки и handles. Скрипт не читает настройки, ключи, содержимое памяти или сетевые пакеты.

Три первых сценария измерены последовательно в одном обычном процессе. Для двух последних запущен отдельный `--ui-preview` без настроек, сопряжения, input hooks, таймеров соединения, сети и аудио. Обычный процесс в это время оставался подключённым в фоне. Это стоимость изолированного интерфейса вместе с .NET и загруженными компонентами, а не точная стоимость WinForms отдельно. Вычитать память одного процесса из другого некорректно из-за общих страниц и разного жизненного цикла.

Снимки UI и переключения выполнялись между замерами. Во время каждого замера агент не генерировал ввод и не снимал интерфейс. Физические движения мыши пользователя, фоновые приложения и состояние системы не фиксировались и не контролировались. Это наблюдение текущей рабочей сессии, а не лабораторный тест неподвижной мыши. Начальный прогрев, сборщик мусора и другие события могут влиять на короткие выборки; обе выборки preview сохранены, повтор оказался выше первого.

Каждый интервал составил примерно 30,3 секунды. Разница между открытым окном и треем наблюдалась в этой последовательности, но без повторов с одинаковой физической нагрузкой её нельзя полностью приписать отрисовке. Сам факт, что повторный preview выше подключённого трея, показывает вариативность; причины CPU-пиков не установлены.

Средняя нагрузка в этой сессии невелика относительно всего CPU. Окно в трее сохраняет почти тот же рабочий набор, поскольку приложение и его сессия остаются живыми. Данных недостаточно для вывода об отсутствии рывков, влиянии на игры или превосходстве над Electron/WPF/WinUI. Секундное измерение CPU скрывает короткие задержки; GPU, DPC/ISR, задержки hooks/WASAPI, аллокации и паузы GC не измерялись. Размер EXE не является рабочим набором.

Счётчик прерываний аудио был 5 перед замерами и после первых двух сценариев; после завершения замеров и возврата в параметры наблюдалось 6. Причина и точное время дополнительного прерывания не установлены. Прослушивание не выполнялось; эти CPU/RAM-замеры не подтверждают качество звука.

## Повторение

```powershell
# Выберите PID обычного EdgeLink или отдельного --ui-preview.
Get-Process EdgeLink | Select-Object Id, Path, MainWindowHandle
.\Measure-EdgeLink.ps1 -TargetProcessId <PID> -Scenario 'connected-home-visible' -OutputFile '.\result.json' -Samples 30
```

Следующий этап при необходимости: несколько повторов с одинаковыми условиями, отдельно неподвижная мышь и фиксированная нагрузка 4000/8000 Гц, затем профиль CPU/GC и задержек. Для сравнения оболочек нужны одинаковые минимальные интерфейсы и условия на том же ПК. Обычный EdgeLink после измерений оставлен работающим; preview закрыт, личные настройки не менялись.
