# Нативная проверка WinUI 3

11 октября 2026, локальный Windows-ПК. Финальные исходники: `311f7eaee71f7a8b7e68d6a2ff197e96a68d6c08`, ветка `windows/input-validation`, версия 0.3.4. Сведения о Windows, SDK, EXE и SHA-256 — в `build.json`.

`input-checks.json`: четыре нативные проверки ввода. `layout-checks.json`: 84 случая / 0 ошибок при 96 DPI. `tray-checks.json`: восемь проверок Shell и жизненного цикла. `software-checks.txt`: 39 PASS. `ui-loop-regression.json`: новый тест падает на коде до исправления и проходит после него; используются только loopback-сокеты и временный случайный ключ в памяти. Это программная проверка, физических HID/наушников она не касается. `live-checks.json`: проверки на установленном приложении через Computer Use. В обычном режиме сохранилось сопряжение и автоматически восстановилось соединение с Mac.

PNG получены через RenderTargetBitmap в изолированном `--layout-checks`, без личных настроек и ключа. Начальное и длительное состояние вкладок проверены также через нативное окно. `runtime-modules.json` подтверждает загрузку WinUI / App Runtime из папки извлечения самодостаточного EXE; этот файл получен на сборке `76501e6`, до изменения только сетевых циклов.

Все нативные проверки финального EXE выполнялись после штатного выхода обычного приложения. X скрывает окно: перед проверками и заменой EXE необходим «Выйти из EdgeLink». Установщик не запускался, Windows не завершалась. Полная проверка Swift ↔ .NET требует Mac; здесь выполнен автономный .NET-набор.

## Ресурсы

Для каждого сценария — 30 секунд / 30 выборок, скрипт `../windows-performance-2026-10-11/Measure-EdgeLink.ps1`. CPU нормирован на 16 логических процессоров: 100% означает всю машину. Working set и private committed — разные показатели, не размер EXE. GPU, DPC, короткие задержки, длительность GC и полная задержка звука не измерялись.

`performance-preview.json` относится к WinUI-коммиту `6ae8052` (без сети, настроек, ввода и звука): 152,6 МиБ working set / 103,1 МиБ private, средний CPU 0,181%. В WinForms-preview ранее наблюдались 66–67 МиБ / 17,8–18,6 МиБ private и CPU 0,251–0,412%. Это подтверждает рост памяти в данном наблюдении; случайные секундные CPU-выборки не доказывают превосходство какого-либо фреймворка.

`performance-connected-home-before-background.json` относится к `76501e6`: 190,8 МиБ working set / 129,6 МиБ private, средний CPU 0,535%, секундный максимум 1,930%. Фоновые сетевые циклы в этой сборке ещё могли зависеть от UI. Финальная сборка измерена отдельно в `performance-connected-home.json` и `performance-connected-tray.json`; точные выборки и сводки находятся в этих JSON.

На финальной сборке средний CPU главной страницы — 0,403%, working set 185,5 МиБ / private 125,5 МиБ. В трее — CPU 0,071%, working set 224,1 МиБ / private 162,9 МиБ. Перед треем впервые открывались параметры; разницу памяти нельзя приписывать самому скрытию окна. В короткой выборке трея working set находился в диапазоне 223,9–224,5 МиБ. Полный анализ длительного роста памяти не проводился.

Окно, соединение и выход проверены на реальном приложении. `audio-tray-continuity.json`: пакеты увеличились с 20 984 до 32 024 через скрытие/восстановление, аудиопрерывания остались 2. `user-feedback.json`: пользователь сообщил 4000 Гц и подтвердил хорошую работу курсора и звука. Это аппаратная пользовательская оценка, агент частоту опроса не измерял и наушники не слушал; 8000 Гц и подробная последовательность всех переходов/клавиш ещё не подтверждены. Во время замеров физическая мышь, фоновые приложения и поток звука Mac не контролировались. Не следует превращать эти наблюдения в строгий сравнительный benchmark.

Дальнейшие проверки: физические переходы и клавиши, прослушивание, повторяемая нагрузка мыши и профиль коротких задержек; другие DPI; реальный OTA-переход и повторный запуск после обновления.
