# Dota 2: физический замер мыши, 11 октября 2026

Установленные исходники `bd1ffc09283ea0ba2b645ba8c78afb2a80759b63`, версия 0.3.4, SHA-256 `dc2af50a05bdbc8e95eee031d8410278ab32bd97872c20bd6ee9f2d05a0dde2e`. Пользователь открыл Dota 2 и подтвердил Lamzu на 4000 Гц; ощущения после первого прогона: «вроде все норм». Затем сравнили чистый игровой интервал с EdgeLink в трее и свежий интервал после полного закрытия приложения на том же физическом Windows-ПК. После сравнения пользователь сообщил: **«Разницы не заметил»**. EXE/код не заменялись; нативное UI-управление во время самих выборок не использовалось.

## Чистый прогон

После подтверждения готовности пользователь получил 5 секунд на возврат в Dota 2, затем выполнил обычное физическое движение мышью. Тот же отдельный пассивный observer, что в предыдущем A/B, работал с 3 секундами прогрева и 20 секундами выборки. Исходник observer идентичен опубликованному [`../windows-mouse-impact-2026-10-11/observer/Program.cs`](../windows-mouse-impact-2026-10-11/observer/Program.cs). Tiered compilation выключена только для observer. Он всегда передаёт ввод дальше, не создаёт синтетический ввод; его WH_MOUSE_LL и Raw Input находятся в отдельном процессе и снимаются по завершении.

Параллельный пассивный sampler раз в 250 мс проверял клиентскую область текущего активного окна по тому же геометрическому правилу покрытия основного монитора. Он не активирует окна, не устанавливает input hooks, не сохраняет названия/процессы/координаты/клавиши. После своего 3-секундного прогрева выполнены **80 проверок: 80 полноэкранных, 0 обычных, 0 недоступных, 0 смен активного окна**. Это исключает наблюдавшуюся в первом прогоне смесь окон; короткое переключение между двумя пробами теоретически может быть пропущено. Процессы начинают/завершают выборки независимо, с небольшой разницей границ. Внутреннее состояние работающего EdgeLink не инспектировалось; отключение edge timer проверено ранее отдельной нативной диагностикой.

CPU агрегируется за весь интервал 23,0204 секунды, включая прогрев; сама цепочка измеряется только 20 секунд. CPU дополнительного Python sampler не измерялся отдельно. Обе измерительные программы добавляют собственную нагрузку.

## Свежий контроль без EdgeLink

По прямому запросу пользователя выполнен off-прогон внутри Dota 2. Подготовка штатного выхода через Computer Use была прервана физической клавишей Esc; дальнейшие UI-действия остановлены. Пользователь сам полностью закрыл EdgeLink и явно попросил запустить контроль. Отсутствие процесса проверено непосредственно перед observer и после его выхода. Приложение после контроля оставлено закрытым. Перед контрольным запуском — 5 секунд на возврат в игру, затем тот же observer и тот же geometry sampler, 3 с прогрева + 20 с физического движения. Контрольный sampler также увидел **80/80 полноэкранных проб, 0 обычных/недоступных, 0 смен активного окна**.

В off-прогоне также нет downstream suppressions, потерянных timing samples и ошибок Raw. CPU observer — 0,3607% всей машины. Поля target CPU равны 0, а версия/working set null, потому что целевого EdgeLink-процесса нет. Типичные времена находятся у предела точности этого observer; разница средних около 0,00001014 мс (10 нс) не доказывает ускорение с приложением. Заметное добавочное ожидание старого постоянного mouse hook в этих выборках не воспроизводится. Пользователь после двух чистых интервалов: «Разницы не заметил». Это не доказательство точного равенства полной задержки или отсутствия любого влияния на игру.

Измеряется время оставшейся цепочки CallNextHookEx с планированием/межпроцессными вызовами, а не полная задержка сенсор → изображение. Observer сам устанавливает hook. Raw Input observer получил 2525 / 2657 движений; их интервалы — доставка в фоновый процесс, не измерение USB polling rate/потерь отчётов/игровых рывков. FPS, frame time, input-to-photon latency, GPU и задержка клавиатуры не измерялись; снижение CPU против прежнего прогона с видимым WinUI-окном не приписывается только новому защитному режиму. Ручные траектории/сцена и фоновые условия не зафиксированы механически, последовательность on→off не рандомизирована, короткое переключение между геометрическими пробами может быть пропущено. Аудио/наушники отдельно не оценивались.

## Исключённый первый прогон

`excluded/mixed-alt-tab.json` сохранён для прозрачности: 50 958 событий, среднее 0,00010166 мс, p99 0,0002 мс, максимум 0,0335 мс, CPU EdgeLink 0,1019% всей машины. `excluded/mixed-foreground.json`: 63 полноэкранные проверки, 28 обычных, 1 недоступная, 6 смен активного окна за 23 секунды. Пользователь подтвердил переключения между окнами; секунды 14 и 16 не содержат движения. Этот прогон не используется как чистый игровой контроль или сравнение CPU.

## Воспроизведение и следующий шаг

Собрать прежний `MouseImpact.csproj` из папки observer, затем в PowerShell запустить SDK `dotnet` с `DOTNET_TieredCompilation=0`:

```powershell
dotnet MouseImpact.dll 20 game-clean.json dota2-fullscreen-clean-user-4000hz <EdgeLinkPID>
python foreground-sampler.py foreground-clean.json
```

Запуски выполняются параллельно в скрытых/фоновых процессах, без смены фокуса игры. Для off-контроля полностью закрыть EdgeLink, убедиться в отсутствии процесса и передать observer PID `0`; sampler остаётся тем же. Следующий шаг при необходимости — отдельный сбор frame time и более длинные повторяемые on/off интервалы. Блокировка фактического перехода у края в меню Dota 2 и восстановление после настоящего Alt+Tab не подтверждены этим профилем; 8000 Гц также не проверялись. Исходники приложения не менялись, compile/native fixture checks повторно не запускались для этого измерения.
