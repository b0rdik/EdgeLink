### Причины и исправления

1. **Воспроизведено на Mac:** остановка слушателя в блокирующем accept без клиента не освобождала порт. Прежний код `5c88ee9` на сценарии «подождать клиента → остановить → снова запустить» падает с Address already in use; исправленный проходит 10 циклов. Теперь nonblocking listener и poll ждут listener/self-pipe, Stop будит pipe, и worker закрывает свои дескрипторы. Idle wakeups/дополнительные сетевые пакеты для этого не нужны. EINTR не завершает listener; фатальная ошибка запускает восстановление, старые ошибки отделены поколением, start не перекрывает незавершённые workers.
2. **Ошибка Windows-классификации, найденная по коду:** Explorer desktop покрывает монитор и мог блокировать переходы как игра после скрытия EdgeLink. Теперь исключены GetShellWindow/GetDesktopWindow и shell-классы Progman/WorkerW/taskbar. Добавлена нативная проверка в `--fullscreen-checks`; на Windows здесь не выполнялась. Пользователь подтвердил, что в проблемном трее точно пропадает переход; про звук не наблюдал. Поэтому это подходящее объяснение, но конкретный аппаратный сбой ещё не воспроизведён на Windows.
3. Обычный Windows startup перенесён из Root.Loaded в OnLaunched после Activate; раннее скрытие окна больше не должно оставлять службы незапущенными. Диагностика по-прежнему ждёт XAML. Неудачная инициализация input повторяется при следующем подключении, вместо вечного input=null. Tray-checks дополнены проверкой продолжения reconnect timer. Нативная проверка раннего скрытия/повторного трея остаётся Windows-шагом.
4. Mac async-start получает token: Stop, сон, неактивная сессия и смена адреса отменяют его. Wake и unlock учитываются раздельно. Старый SCStream error игнорируется по identity; запоздалый Windows WASAPI error проверяет текущий output/link, прежде чем отключать их. Эти гонки исправлены по коду, аппаратные ошибки SCStream/WASAPI не симулировались.
5. Windows discovery выполняется вне UI-потока; потерянная проба повторяется максимум 3 раза в прежние 1,5 секунды. Мусорный ответ больше не завершает поиск на адаптере. Loopback-тест теряет первую пробу и посылает мусор/неверный fingerprint перед корректным ответом; поиск завершается. Во время активной связи дополнительных проб нет.

### Обновление: окончательное требование пользователя

Пользователь явно отказался от резервов. Итоговый код **не создаёт backup/rollback copy**. Проверенный новый билд подготавливается рядом с target, затем Mac FileManager replacement или Windows File.Replace заменяет target без backup name. Данные старой установки удаляются при commit; staging/incoming/receipt очищаются. При ошибке проверки до commit установленный файл остаётся прежним. При ошибке запуска после commit новая версия остаётся установленной; отката нет. Сообщения интерфейса соответствуют этому режиму.

Используется startup receipt, чтобы регистрировать неудачный запуск; это не резерв. Windows receipt публикуется атомарно, а helper проверяет сохранённый SHA-256 подготовленного EXE перед заменой. `[NullString]::Value` нужен для настоящего null filename в PowerShell: обычный `$null` в проверке преобразовался в пустую строку и был отвергнут File.Replace. Legacy-cleanup удаляет только собственные прошлые `.previous-*`: Mac UUID и bundle ID, Windows timestamp и ProductName EdgeLink; символические ссылки/reparse points и произвольные имена исключены.

## История: Keep Awake на Mac

По запросу пользователя добавлен Keep Awake: переключатель на главной странице и пункт меню EL «Keep Awake — не давать Mac уснуть». Функция включена по умолчанию; выбор сохраняется в локальном UserDefaults и применяется при каждом запуске. Она работает всё время жизни EdgeLink, включая ожидание ПК и скрытое окно, независимо от состояния связи.

Используется один process-owned `IOPMAssertionTypePreventUserIdleDisplaySleep`, который предотвращает автоматический сон экрана и тем самым idle system sleep. Таймеры, имитация ввода и дочерний caffeinate не нужны. При выключении и `applicationWillTerminate` assertion освобождается; deinit также освобождает его. Preview не создаёт assertion. Явный сон, закрытие крышки и штатная политика питания macOS не переопределяются. Основание: [Apple IOKit](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventuseridledisplaysleep) и локальный SDK IOPMLib.h.

Проверенные и установленные исходники: `aa2763fe7ac76604eaf2121db24d0552bf219fe5`, версия 1.0.0. Нативная проверка IOKit **10/10**: создание, тип/уровень assertion, повторное включение без дубликата, выключение, повторное выключение, повторное включение и deinit. Она включена в `source/run-checks.sh`; полный прогон Swift/.NET с `EDGELINK_SKIP_DISCOVERY_CHECK=1` завершился exit 0. Проверка иконок bundle — 11/11; ресурсы и протокол не менялись.

Сборка установлена в `/Applications/EdgeLink.app` после штатного выхода; прежняя версия сохранена локально вне Git. Подпись сохранена, TCC и ключ сопряжения не менялись. На настоящем интерфейсе macOS проверены видимость карточки, переключение on/off и пояснения. Через `pmset -g assertions` подтверждены отсутствие assertion после выключения, ровно один после включения и отсутствие после выхода. Проверены перезапуски с выключенным и включённым выбором. Итоговая установка оставлена запущенной с Keep Awake **включённым**. После замены связь с ПК восстановилась автоматически; новые физические проверки клавиатуры/курсора и прослушивание звука не заявляются. Пункт глобального меню EL добавлен и собран; его интерактивное нажатие инструментом не проверялось.

Результаты: [`validation/mac-keep-awake-2026-10-11/`](validation/mac-keep-awake-2026-10-11/). SHA-256 executable: `2b1dc6f2c0e6b3236f93ee6452b1fbfb5380685531490ecafa8cff140a14f6f1`. Полный цикл ожидания реального idle sleep, закрытие крышки и принудительный сон не выполнялись, чтобы не прерывать рабочую сессию; проверено состояние штатного assertion, а не обещана блокировка всех видов сна.

Windows-код не менялся; новый Windows EXE ради этой функции не требуется. Ветка обмена остаётся `mac/el-icon-validation`. Публичный релиз/OTA остаётся v0.3.4; эта проверочная Mac-сборка 1.0.0 обновлена локально.
