# EdgeLink 0.3.4

Клавиатура и мышь Windows управляют Mac при переходе курсора через край экрана. Системный звук Mac поступает в выбранный аудиовыход Windows и смешивается со звуком ПК. По умолчанию Mac расположен **слева**.

Сборки: Apple Silicon, macOS 15 или новее; Windows x64, целевой сценарий Windows 11. Windows-приложение содержит runtime .NET — отдельно устанавливать его не нужно. Это экспериментальный релиз: реальная задержка и работа конкретных HID/аудиоустройств требуют проверки на двух компьютерах.

## Меньше нагрузки от мыши на Windows в 0.3.4

В рабочей ветке `windows/input-validation` интерфейс Windows перенесён на WinUI 3: стандартные элементы Fluent, верхние вкладки, компактная схема экранов и адаптивные карточки. Это проверочная сборка 0.3.4; опубликованный релиз пока не менялся.

Крестик скрывает окно в системный трей, сохраняя соединение и звук. Чтобы открыть окно, дважды нажмите значок EdgeLink в трее, выберите «Открыть EdgeLink» или запустите EXE ещё раз. Для полного завершения выберите «Выйти из EdgeLink» в меню значка или в кнопке «Меню» в окне. Перед заменой EXE и диагностикой используйте именно этот выход. Обновление и завершение сеанса Windows могут закрывать процесс штатно.

Дополнительная диагностика `EdgeLink.exe --tray-checks` проверяет настоящий значок Shell и жизненный цикл окна; отчёт — `%TEMP%/EdgeLink-tray-checks.json`. `EdgeLink.exe --ui-preview` открывает изолированный интерфейс без личных настроек, ключа, перехвата ввода, сети и звука.

В рабочей ветке на ПК постоянный перехват мыши отключён вместе с Raw Input. Отдельный поток проверяет позицию курсора обычным таймером Windows с интервалом 16 мс только при подключённом Mac; при отключении проверка останавливается. Это убирает ожидание потока EdgeLink из обычной обработки каждого движения мыши Windows. Сам переход на Mac может реагировать позже на один или несколько интервалов таймера под нагрузкой. Для перехода нужно новое движение к краю; удерживаемые клавиши и кнопки блокируют перенос, после возврата требуется движение внутрь экрана и действует пауза 200 мс.

На время управления Mac включаются mouse hook, Raw Input с одним заранее выделенным буфером и повышенная точность таймера; при возврате на ПК они снимаются. Клавиатурный hook остаётся на отдельном потоке для контроля удерживаемых клавиш и Ctrl+Alt+Esc. Работа интерфейса не блокирует этот поток. Протокол и обработка звука не изменены.

В параметрах «Игры и полный экран» по умолчанию включена автоматическая блокировка переходов, когда активное приложение занимает весь выбранный экран ПК. Она охватывает режим «полноэкранный в окне», включая меню игры, а также полноэкранное видео и браузер. Это правило размера активного окна, а не распознавание игры по названию. Обычное развёрнутое окно с заголовком или панелью задач не блокируется. Звук продолжает работать. После Alt+Tab или выхода из полного экрана отведите курсор хотя бы на 6 пикселей от края перед новым переходом; действует пауза 200 мс. Переключатель применяется сразу и сохраняется локально.

Полноэкранная защита получает асинхронные события смены активного окна и изменения его геометрии. Проверки списка процессов и поиск окон по таймеру не используются; события геометрии ограничены потоком активного окна. Пока переходы заблокированы, таймер проверки края полностью остановлен. Перед самим переносом выполняется дополнительная проверка активного окна, чтобы закрыть задержку доставки события фокуса. Диагностика `EdgeLink.exe --fullscreen-checks` проверяет эту логику на настоящем полноэкранном окне WinUI и записывает `%TEMP%/EdgeLink-fullscreen-checks.json`; она не заменяет проверку конкретной игры и её FPS.

Отправка движений просыпается только при изменении позиции, объединяет частые события в последнюю позицию и сохраняет выбранное ограничение частоты пакетов. Постоянного таймера отправки на неподвижной мыши нет. Это уменьшает лишнюю работу с мышами 4000–8000 Гц; частоту опроса самой мыши приложение не изменяет. Аудиобуфер и протокол соединения остаются совместимыми с Mac 0.3.3, его обновление для этого исправления не требуется.

На Windows нажмите «Проверить обновления» и подтвердите установку 0.3.4. EXE будет заменён и запущен заново; ключ и настройки сохранятся. Для ручной установки полностью закройте приложение и замените EXE в прежней папке.

Диагностика `EdgeLink.exe --input-checks` проверяет отдельный поток ввода, отсутствие mouse hook и Raw Input на ПК, остановку проверки края при отключении и потере связи, нативные циклы установки/снятия hook, запуск/остановку таймера и ответ потока при остановке интерфейса на 300 мс. Политика перехода проверяется для обеих сторон, удерживаемого ввода и повторного входа. Отчёт — `%TEMP%/EdgeLink-input-checks.json`. Режим не использует сопряжение, сеть, воспроизведение звука или искусственное движение курсора; нативные проверки выполняются непосредственно на Windows.

## Плавный звук и отключение динамиков в 0.3.3

Windows учитывает реальный размер порций звука, поступающих с Mac, и размер запроса WASAPI. Воспроизведение начинается, когда хватает данных на целый запрос плюс резерв. При опустошении резерв увеличивается по 5 мс, максимум до 60 мс; старый остаток сбрасывается, переход в тишину и возврат сглаживаются. Это адаптивный запас, а не измерение полной задержки. Выберите «Авто — от 10 мс»; варианты от 20/40 мс задают больший минимальный резерв. Размер порций передаётся внутри существующих handshake/heartbeat, без дополнительного потока пакетов.

На Mac по умолчанию включено «Выключать динамики Mac, пока подключён ПК» в параметрах звука. При отключении, остановке или выходе возвращается только состояние mute, изменённое EdgeLink; громкость остаётся прежней. Уже выключенный звук не включается, ручное включение во время связи учитывается. При смене аудиовыхода восстанавливается прежний выход. После аварийного завершения восстановление выполняется при следующем запуске EdgeLink. Для аудиовыходов без системного mute интерфейс предложит выключить звук вручную.

## Исправление обрыва связи в 0.3.2

Исправлено аварийное завершение Mac-приложения при обработке системного звука: после удаления отправленного PCM-пакета диапазон следующего пакета рассчитывается от фактического начала `Data`. Ошибка приводила к исчезновению Mac из поиска и сообщению Windows «Unable to read beyond the end of the stream». Windows теперь показывает понятное сообщение при закрытии соединения. Для устранения причины обновите приложение на Mac.

## Исправление интерфейса Windows в 0.3.1

Исправлена раскладка карточек: ширина задаётся доступной областью страницы, высота рассчитывается по тексту и полям. Убрана взаимная автоматическая подгонка размера вложенных контейнеров. Длинные строки переносятся, страницы прокручиваются по вертикали, в узком окне подписи полей располагаются над значениями. Стартовое окно учитывает рабочую область экрана; задана базовая плотность 96 DPI и режим PerMonitorV2.

Чтобы заменить EXE вручную, полностью закройте EdgeLink на Windows и положите новый `EdgeLink.exe` на прежнее место. Настройки и сохранённый ключ подключения находятся отдельно и сохраняются. Mac 0.3.0 совместим с Windows 0.3.1.

Для проверки на Windows доступен диагностический запуск `EdgeLink.exe --layout-checks`: он проверяет реальные границы элементов при разных размерах окна, переключение разделов, перенос селекторов и длинные сообщения. Отчёт и снимок мастера сохраняются в `%TEMP%/EdgeLink-layout-checks`. В этом режиме не используются ключ подключения, настройки, сеть, захват ввода и аудио. Проверку нужно выполнять на Windows; компиляция на Mac не подтверждает визуальный результат.

## Что нового в 0.3.0

Windows: новый тёмный интерфейс с навигацией «Главная / Подключение / Параметры», отдельный мастер первого запуска, перетаскивание файла сопряжения и один экземпляр приложения на пользовательскую сессию. Файл, открытый повторно, передаётся работающему экземпляру. Иконка ICO содержит 16/24/32/48/64/128/256 пикселей, встроена в EXE и загружается напрямую для окна/панели задач; отдельный `EdgeLink.ico` включён в Windows ZIP.

Mac: компактный интерфейс с главной страницей, параметрами и четырьмя шагами настройки. Проверка разрешений использует реальные API управления/записи, есть явная перепроверка ScreenCaptureKit, перезапуск и восстановление устаревших разрешений. Получение ключа из Keychain и поиск Ethernet выполняются вне главного потока. Cmd+Q завершает приложение.

## Разрешения включены, но приложение их не видит

macOS связывает доступ с подписью программы. У предыдущих ad-hoc сборок подпись менялась при пересборке: переключатель мог оставаться включённым, а TCC отклонял новую версию как не соответствующую старой записи. В диагностированной установке это подтверждено журналом TCC: сохранённый и текущий cdhash различались.

Текущая Mac-сборка подписана стабильной Apple Development подписью. Это не Developer ID/notarization; Gatekeeper может потребовать штатного подтверждения запуска. Для перехода со старой ad-hoc версии доступ нужно обновить **один раз**:

1. В EdgeLink: «Первое подключение» → «Разрешения» → «Уже включено, но не работает…».
2. Подтвердите «Обновить разрешения». Сбрасывается только доступ `local.edgelink.mac` к управлению и записи экрана, ключ и настройки сохраняются. Самостоятельного сброса при запуске или обновлении нет.
3. После перезапуска откройте настройки кнопками в мастере и включите EdgeLink заново. Подтвердите системный запрос macOS самостоятельно, если он появится.
4. Вернитесь в EdgeLink и нажмите «Проверить снова». Галочки отображаются только после фактической проверки. Если macOS просит перезапуск, используйте соответствующую кнопку.

На macOS 27 управление находится в разделе «Device Control and Data Access» («Управление устройством и доступ к данным»), запись — в «Screen & System Audio Recording». В предыдущих версиях название управления может быть «Accessibility». Если восстановление через `tccutil` не удалось, удалите прежнюю запись EdgeLink в этих двух списках и добавьте **установленный** `/Applications/EdgeLink.app` заново. Копии в разных папках и сборки с другими подписями могут требовать отдельного подтверждения.

Подпись следующих обновлений должна оставаться той же. Скрипт сборки использует доступную Developer ID/Apple Development identity; можно явно указать `EDGELINK_SIGN_IDENTITY`. Без сертификата fallback остаётся ad-hoc, с прежними ограничениями TCC.

## Быстрая настройка

1. Соедините свободные Ethernet-порты Mac и ПК обычным кабелем Cat5e/Cat6. Оставьте IPv4 в автоматическом режиме на обоих адаптерах. Без DHCP операционные системы обычно назначат адреса `169.254.x.x`; это может занять некоторое время. Для отдельного кабеля шлюз, DNS, мост и общий доступ к интернету не нужны.
2. Переместите `Mac/EdgeLink.app` в постоянную доступную для записи папку, например `~/Applications`, и запустите. В строке меню появится значок двух экранов.
3. В мастере «Первое подключение» на шаге «Разрешения» откройте настройки управления мышью/клавиатурой и записи экрана/системного звука соответствующими кнопками. Включите EdgeLink в открытых настройках macOS. Галочка появляется по результату проверки разрешения, а не просто после нажатия кнопки. Состояние проверяется каждую секунду и при возвращении в приложение. Если macOS требует перезапуск, выполните его.
4. На шаге «Сопряжение» сохраните файл `.edgelink` и перенесите его на свой ПК. Файл содержит секретный ключ доступа к Mac: после импорта храните его приватно или удалите. Ключ не публикуется и не передаётся в GitHub.
5. Запустите `Windows/EdgeLink.exe` из постоянной папки. В мастере первого подключения нажмите «Добавить Mac…» или перетащите файл в окно. После первого запуска Windows также регистрируется открытие `.edgelink` двойным кликом; файл передаётся уже работающему экземпляру приложения.
6. На шаге проверки связи нажмите «Разрешить соединение по Ethernet…» на Windows и подтвердите системный запрос администратора, если firewall блокирует обнаружение или звук. Приложение добавляет правила только для своего исполняемого файла, проводных интерфейсов и локальной подсети: UDP 48792 для звука и ответы обнаружения с UDP 48794. Firewall не отключается.
7. Выберите аудиовыход на ПК — например, ресивер наушников. Если нужное устройство является выводом Windows по умолчанию, оставьте стандартный вариант. Оставьте «Авто — от 10 мс»; резерв подстроится под захват Mac и аудиодрайвер.

Mac автоматически выбирает Ethernet, предпочитая адреса `169.254.*`, и начинает ожидать ПК после получения разрешений. Если проводных адаптеров несколько, выберите нужный в интерфейсе. ПК ищет Mac на проводных IPv4-интерфейсах без шлюза либо с link-local адресом, сверяет отпечаток ключа, затем устанавливает шифрованное соединение. Ключ сохраняется в Keychain на Mac и Credential Manager на Windows; в обычном файле настроек ключа нет.

Windows повторяет соединение каждые 10 секунд, пока включён соответствующий переключатель. Mac возобновляет ожидание после сна/разблокировки и смены Ethernet-адреса. Ручные кнопки «Остановить»/«Отключить» приостанавливают автоматическое подключение до явного нового подключения или следующего запуска. Автозапуск приложений при входе в ОС пока не включён.

Разрешения конфиденциальности macOS и подтверждение администратора Windows выдаёт пользователь: приложение открывает нужные страницы и выполняет оставшиеся шаги автоматически.

## Если автоматический адрес не появился

Для свободной подсети можно вручную назначить:

| Параметр | ПК | Mac |
| --- | --- | --- |
| IPv4 | `192.168.233.1` | `192.168.233.2` |
| Маска | `255.255.255.0` | `255.255.255.0` |
| Шлюз / Router | пусто | пусто |
| DNS | пусто | пусто |

На Windows: `Win + R` → `ncpa.cpl` → нужный Ethernet → Свойства → IPv4. На Mac: Настройки системы → Сеть → нужный Ethernet → Подробнее → TCP/IP. Меняйте только адаптер отдельного кабеля. Если подсеть пересекается с домашней сетью/VPN, выберите другую. Приложения сами адреса и маршруты ОС не меняют.

Автоматический поиск работает и с такими адресами. Для явного подключения выключите автоматический режим и укажите адреса в обоих приложениях; пустой адрес ПК на Mac допускает любого клиента, прошедшего проверку ключа.

## Управление

Курсор уходит за левый край выбранного монитора ПК и появляется у правого края выбранного экрана Mac. Возврат — за правый край Mac. Клавиатура переключается вместе с мышью. Переход выполняется, когда клавиши и кнопки отпущены; после возврата отведите курсор немного внутрь экрана ПК, чтобы не переключиться обратно сразу.

**Ctrl + Alt + Esc** немедленно возвращает управление на ПК. Отключение приложения делает то же самое. Потеря связи освобождает курсор ПК и удерживаемые клавиши/кнопки Mac после обнаружения разрыва — в пределах нескольких секунд.

По умолчанию Ctrl ПК соответствует Command Mac, Windows — Control, Alt — Option. Буквы передаются как физические клавиши: раскладку выбирает macOS. Fn, команды прошивки клавиатуры и защищённые комбинации Windows могут обрабатываться локально. «Скорость мыши на Mac» задаёт линейное соотношение движения и координат; профиль ускорения Windows не воспроизводится.

Целевой сценарий — обычный рабочий стол после входа в систему. Экран входа/FileVault, UAC и защищённый рабочий стол, общий буфер обмена, перенос файлов и переходы сверху/снизу не реализованы. Поддерживается выбранная пара экранов; после изменения набора мониторов перезапустите приложения.

## Сеть, звук и задержка

Системный звук: 48 кГц, стерео PCM16, пакеты по 5 мс. Микрофон не захватывается. Аудиотрафик — около **1,65 Мбит/с** с IPv4/UDP, немного больше с Ethernet. Мышь отправляет до 1000 небольших пакетов в секунду только при движении, до ~0,68 Мбит/с с IPv4/UDP; можно выбрать 500/250 Гц. Изображение экрана по сети не передаётся. Управление и звук привязаны к выбранным Ethernet-адресам; отдельный кабель не занимает Wi-Fi. Поиск использует короткие UDP-запросы до установления соединения. Проверка обновлений обращается к GitHub через обычное интернет-соединение раз в сутки.

Управление и звук шифруются AES-256-GCM с новым ключом сеанса. Пакеты мыши ограничены частотой, движения объединяются; клики и клавиши идут по надёжному каналу. Аудиобуфер ограничен, отбрасывает устаревшие пакеты и компенсирует небольшое расхождение часов. Адаптивный резерв учитывает размер захвата и повышается при прерываниях; варианты от 20/40 мс задают больший минимум. Сжатие Opus не включено; PCM уменьшает расходы на кодирование.

Динамики Mac автоматически выключаются при подключённом ПК; этот режим можно выключить в параметрах звука. Защищённый медиаконтент может не попадать в захват. ScreenCaptureKit создаёт минимальный внутренний видеопоток, но приложение подписывается только на аудио и не отправляет видеоданные.

Windows показывает RTT, трафик и заполнение аудиобуфера. Эти показатели **не равны полной задержке**: в неё входят захват, ОС, драйвер и ресивер наушников. Полная задержка на физических компьютерах пока не измерена. WASAPI работает в shared event-driven режиме с запрошенным буфером 10 мс; IAudioClient3 не реализован.

## Обновления из GitHub

Публичный репозиторий: [b0rdik/EdgeLink](https://github.com/b0rdik/EdgeLink). Оба приложения проверяют последний стабильный GitHub Release раз в сутки при запуске; есть ручная кнопка. Скачивание и установка начинаются после подтверждения в приложении.

Обновление проверяет адрес GitHub, размер, SHA-256 из Release API, структуру архива, платформу и внутреннюю версию. На Mac дополнительно проверяется подпись bundle. Установка сохраняет предыдущую версию рядом, заменяет приложение и перезапускает его; при ошибке замены пытается восстановить предыдущую версию. Папка установки должна быть доступна для записи. Номер версии задаётся файлом `VERSION`.

Mac подписан Apple Development, но пока без Developer ID/notarization; Windows — без Authenticode: на первом запуске возможны Gatekeeper/SmartScreen. Пользуйтесь штатным разрешением первого запуска, не отключая защиту целиком. При смене подписи macOS потребует повторно выдать разрешения; при обновлении может отдельно запросить доступ к сохранённому ключу Keychain. Для полностью бесшовных обновлений Mac потребуется стабильная Developer ID подпись. С версии 0.2.0 доступно OTA: нажмите «Проверить» и установите 0.3.1. С версии 0.1 обновление устанавливается вручную.

## Проверки и пересборка

Проверены сборки обеих платформ, криптография/неверный ключ, Swift ↔ .NET handshake, обнаружение с nonce/отпечатком без передачи ключа, UDP-звук, heartbeat/разрыв, повторное открытие портов, ограничение аудиобуфера, обработка старых пакетов и разрывов, разбор метаданных обновлений, запрет downgrade/опасных архивов. Проверены первичная группа иконок Windows в PE и стабильность designated requirement при изменении подписанного bundle. На Mac выполнена реальная замена отдельного тестового bundle и отклонение повреждённой подписи. Новый SwiftUI интерфейс проверен визуально в безопасном preview-режиме. Подробности в `verification.txt`.

Windows-оболочка в ветке `windows/input-validation` переведена на WinUI 3 / Windows App SDK. Самодостаточный EXE включает .NET 10 и Windows App Runtime; MSIX и отдельная установка runtime не требуются. Крестик скрывает окно в трей, полный выход доступен в «Меню → Выйти из EdgeLink» и меню значка трея. Опубликованный релиз 0.3.4 ещё использует прежнюю оболочку. Результаты нативных Windows-проверок и текущий коммит: `docs/HANDOFF-WINDOWS.md`.

Пользователь подтвердил физические переходы, удержание клавиш/кнопок, курсор и звук при 4000 Гц на предыдущих сборках этой ветки; игровой on/off в Dota 2 не выявил измеримого влияния на наблюдаемую цепочку мыши. Точные версии и ограничения указаны в `docs/HANDOFF-WINDOWS.md`. После финальной очистки нативные проверки повторены; новый аппаратный A/B не проводился. Ещё требуют проверки: установщик PowerShell с новой оболочкой, 8000 Гц, физическая блокировка края игры, FPS и полная задержка наушников.

Mac: Xcode Command Line Tools, `bash source/build-mac.sh`. Windows: .NET SDK 10 на Windows, `powershell -ExecutionPolicy Bypass -File source/build-windows.ps1`; XAML-компилятор WinUI требует Windows. Иконки: `python3 -m pip install -r source/assets/requirements-icons.txt`, затем `python3 source/assets/build-icons.py` на Windows или Mac. Готовые ресурсы уже находятся в Git; для обычной сборки Python не нужен. Проверки протокола: `bash source/run-checks.sh` на Mac с установленным .NET SDK 10. Публикация сборок описана в `source/RELEASING.md`. Лицензии NAudio и .NET включены в `licenses/`.
